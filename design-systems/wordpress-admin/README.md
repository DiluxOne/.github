# wordpress-admin

The admin screens of a DiluxOne WordPress plugin. Version 0: extracted from
what [Offload](https://github.com/DiluxOne/diluxone-offload-wordpress) and
[Users+](https://github.com/DiluxOne/diluxone-users-wordpress) already draw,
and mapped to the WordPress admin palette where they match. Nothing in it
is new; what the two plugins disagree on is listed below with the value
chosen.

- [`tokens.json`](tokens.json): the tokens, in the Design Tokens format.
- [`dist/tokens.css`](dist/tokens.css): the same as CSS custom properties,
  generated by [`scripts/design-tokens.py`](../../scripts/design-tokens.py).
- [`components.md`](components.md): tabs, cards, notices, tables, forms,
  pills and the screen's layout, each with its example.
- [`rules.yml`](rules.yml): what a review checks.

## Principles

1. **WordPress's pieces first.** `.nav-tab-wrapper`, `.wp-list-table`,
   `.notice`, `.button`, `.card` do what they can; what a plugin adds on top
   is rank (a title that reads as a title, a state you see without reading),
   not a look of its own.
2. **The accent is the person's.** The plugin reads the admin colour scheme
   the person picked and sets `--dx-color-accent` from it; the wash, the
   edge, the focus ring, the open tab and the info notice follow. The blue
   in the tokens is the default scheme's, the fallback.
3. **Tokens, not numbers.** A colour, a space, a radius, a size is a
   property of [`dist/tokens.css`](dist/tokens.css). A number typed into a
   rule is where two screens start to differ.
4. **One measure.** What is read stops at `--dx-layout-measure` (1000px); a
   table or a grid of cards takes the width it is given.
5. **WordPress's breakpoints only.** 782px (touch) and 960px (the menu
   folds).

## Using it in a plugin

1. Copy `dist/tokens.css` from one of the organisation's tags into the
   plugin (`assets/css/dx-tokens.css`), and say which tag in the commit.
2. Enqueue it on the plugin's own screens only, before its admin stylesheet,
   which depends on it.
3. Set the accent from the person's scheme, on the same handle:

   ```php
   $scheme = get_user_option( 'admin_color' ) ?: 'fresh';
   $colors = $GLOBALS['_wp_admin_css_colors'][ $scheme ]->colors ?? array();
   $accent = sanitize_hex_color( $colors[2] ?? '' ) ?: '#2271b1';
   $light  = sanitize_hex_color( $colors[3] ?? '' ) ?: '#72aee6';
   wp_add_inline_style( 'diluxone-example-tokens', ":root{--dx-color-accent:{$accent};--dx-color-accent-light:{$light}}" );
   ```

4. Write the screen with the properties and the components; check it
   against [`rules.yml`](rules.yml).

## The tokens

| Group | Properties | From |
| --- | --- | --- |
| Palette | `--dx-color-wp-*`: the WordPress admin colours the plugins use (gray, blue, red, yellow, green) | wp-admin's palette |
| Text | `--dx-color-text`, `-muted`, `-subtle` | gray 90, 50, 60 |
| Lines | `--dx-color-border`, `-strong`, `-soft` | gray 5, 10, 2 |
| Grounds | `--dx-color-surface`, `-alt` | white, gray 0 |
| Accent | `--dx-color-accent`, `-light`, `-wash` (8% on white), `-edge` (45%) | the person's scheme |
| States | `--dx-color-success`, `-warning`, `-error`, `-info`, each with its `-wash` (and `-text`, `-strong` where used) | WordPress's notices |
| Pills | `--dx-color-pill-{on,pending,off}-{background,text}` | both plugins, identical |
| Pro | `--dx-color-pro`, `-wash` | Users+ |
| Space | `--dx-space-1` to `-6` (4, 8, 12, 16, 24, 32px), `--dx-space-block` (24px) | Users+'s scale |
| Radius | `--dx-radius-sm` (4), `-md` (6), `-lg` (8), `-pill`, `-round` | both |
| Type | `--dx-font-size-{tiny,small,help,body,title,heading}` (11 to 18px), `--dx-font-weight-{regular,semibold}`, `--dx-font-line-height-{snug,base,pill}` | both |
| Borders | `--dx-border-width` (1px), `-bar` (3px, the accent band), `-notice` (4px) | both |
| Shadows | `--dx-shadow-raise`, `-dialog`, `-focus` | Users+ |
| Motion | `--dx-motion-duration-fast` (120ms) | Users+ |
| Layout | `--dx-layout-measure`, `-rail`, `-card-min`, `-toolbar`, `-toolbar-mobile` | both |
| Breakpoints | `--dx-breakpoint-mobile` (782px), `-menu` (960px), for reading: `@media` cannot use a property | WordPress |

## Where v0 came from

Read from `assets/css/admin*.css` of Offload and
`assets/diluxone-users-admin.css` of Users+ (with Users+'s
`includes/admin-ui.php` for the accent), on `main` on 2026-10-15.

What the two agree on, taken as it is: the WordPress grays for text and
lines, the accent from the scheme (both set it inline: Users+ as
`--du-accent`, Offload as `--diluxone-offload-accent`), the open tab marked
by a 3px top border in the accent, the pill (shape and three colours to the
hex value), the measure of 1000px, 600 as the only heavy weight, the
782px breakpoint.

Users+ already had a token set (`--du-*`, in its stylesheet); where Offload
has no opinion, Users+'s is the one here. Where they differ:

| What | Offload | Users+ | v0 |
| --- | --- | --- | --- |
| Card radius | 8px | 6px | `md` 6px for cards; `lg` 8px kept for Offload's status cards until it moves |
| Light border | `#ddd` (15 times) | `#dcdcde` | `#dcdcde`, the palette's gray 5 |
| The rail's minimum | 240px | 260px | 260px |
| Modal shadow | `0 10px 30px` at 30% | `0 12px 40px` at 20% | Users+'s |
| A space of 20px | padding and margins, often | once | not in the scale: 16 or 24 |
| Breakpoints | 768, 782, 960, 1100, 1400px | 782, 960px | 782 and 960 |
| State badge | `.state-badge` (Bootstrap and Material colours: `#28a745`, `#ffc107`, `#17a2b8`, `#e8f5e9`…) beside the pill | the pill only | the pill; the badge's colours are not in the system |
| Error text | | `#8a1f21` | the palette's red 70, `#8a2424` |

Not taken, because only one screen uses them: Users+'s toggle green
(`#0f7b4f`), Offload's progress stripes (`#c5d9ed` and `#dbe7f3`; the first
is the palette's blue 5 and is in it), the big numbers' sizes (22, 24, 32,
40, 48px).
