# Reusable workflows

Every workflow here, what it does and what it takes; the scripts behind them; and the organisation's secrets and variables.

## Reusable workflows

Call them at `@v5`, every one of them, the release included: never at a pinned commit (`v5` is a protected ref that only an administrator moves, #136); a breaking change ships as the next major (`v6`), and the previous one stays where it is. A stack suffix
(`-wp`) appears only when the steps are specific to that stack. A workflow
with a `central-ref` input reads the scripts, profiles and policy at that
ref (default `v5`), not at the ref of its `uses:` line: a caller that pins
`uses:` to a version passes the same version as `central-ref`.

| [`security-fix.yml`](../.github/workflows/security-fix.yml) | Reusable, called only from a private repository (DiluxOne's is `DiluxOne/security`, every hour and by hand from its default branch; it refuses to run from a public one, whose logs and artifacts anyone could read): a security advisory's fix, written where only the organisation sees it (#194). Each advisory in triage or draft is claimed with an issue in the private repository, "Fix <GHSA> in <repository>" (one attempt per advisory). An agent (Bash and the network, on a stranger's text, with no key or token of the App) clones the public repository, writes a failing test and the fix, and its `make pre-pr` runs in the same job; a patch is all that leaves it. At most two in triage are taken a run (`TRIAGE_PER_RUN`), since a stranger's report starts a paid run with no person in between; a draft stays private and is reviewed before anything is published. The advisory's temporary private fork is not used: GitHub lets only people and teams into it. It never merges nor publishes: `security-patch.yml` publishes a fix whose checks passed once its advisory is a draft and a maintainer approves it (#247, #287). The advisories are read and moved with dilux-security's key (`DILUX_SECURITY_PRIVATE_KEY`, `DILUX_SECURITY_CLIENT_ID`, only in the private repository), so dilux-bot needs no advisory permission; the caller ([`workflow-templates/security-fix.yml`](../workflow-templates/security-fix.yml)) passes `DILUX_BOT_PRIVATE_KEY`, `DILUX_SECURITY_PRIVATE_KEY` and `CLAUDE_CODE_OAUTH_TOKEN` or `ANTHROPIC_API_KEY`. `DX_AUTOPILOT=off` stops it. | `central-ref` |
